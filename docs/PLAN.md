# LeekOrbit 实现计划

依据：`CONTEXT.md` 词汇表、ADR-0001（行为涌现）、ADR-0002（双层记忆）。
细节问题（社媒摘要偏差、唤醒频率具体值、挂单语义、公司行为、模型选型）暂缓，各阶段留了钩子。

## 总体架构

Python 单体，一个进程内三个角色：**平台**（7×24 常驻：调度、数据、交易所、存储）、**Agent**（被唤醒的会话循环）、**仪表盘**（FastAPI，只读）。

```
leekorbit/
├── pyproject.toml
├── docker-compose.yml
├── config/
│   ├── platform.yaml            # 数据源、模型路由、成本上限
│   └── agents/leek-01.yaml      # 人设：背景 + 作息表 + 模型绑定（无行为剧本，见 ADR-0001）
├── leekorbit/
│   ├── platform/
│   │   ├── scheduler.py         # APScheduler：作息表 → 唤醒事件；交易日历感知
│   │   ├── calendar.py          # A股交易日历（节假日、交易时段）
│   │   ├── market/
│   │   │   ├── datafeed.py      # akshare 封装：快照、K线、个股新闻（重试+缓存+降级）
│   │   │   └── social.py        # 人气榜、千股千评、热搜；股吧直抓为可选插件
│   │   ├── exchange/
│   │   │   ├── broker.py        # 账户：可用资金、T+1 冻结、持仓、交易权限
│   │   │   ├── matcher.py       # 撮合：下一快照价成交、涨跌停封板拒单、整手校验
│   │   │   └── fees.py          # 佣金、印花税、过户费
│   │   └── store/
│   │       ├── db.py            # SQLite（WAL 模式）
│   │       └── models.py        # ledger / positions / snapshots / diary / nav
│   ├── agent/
│   │   ├── persona.py           # 人设加载与校验（校验器拒绝含行为指令的人设）
│   │   ├── feed.py              # 信息流组装：按作息场景生成推送内容
│   │   ├── wake.py              # 一次唤醒：feed → LLM 会话 → 动作解析 → 快照存档
│   │   ├── tools.py             # 动作空间：lookup(限3-5次)/order/diary/pass
│   │   ├── memory.py            # 主观日记读写（Agent 只能读到这里，见 ADR-0002）
│   │   └── llm.py               # 分层路由：看盘=便宜模型，决策/复盘=强模型；OpenAI 兼容客户端
│   ├── dashboard/               # FastAPI + 静态前端
│   └── analysis/                # 离线行为标注脚本（二期，仅留目录）
└── tests/
```

关键实现约定：

- **决策快照**存为一行 SQLite 记录，输入（信息流全文、查询结果、当时日记）、模型往返、动作、动作结果整体打包成 JSON 列——回放优先，不做关系化。
- **LLM 客户端**统一走 OpenAI 兼容接口，模型名是配置项——换模型即换被试（ADR-0001 推论），代码不感知厂商。
- **账本是唯一事实**：交易所写 ledger，持仓/净值全部由 ledger 推导，禁止两处记账。
- **Agent 读数据的唯一通道**是 feed.py 和 tools.py——ADR-0002 的「账本不喂回」靠这个收口保证，而不是靠自觉。

## 阶段划分

每个阶段有明确的完成标准，按序做，纵向切片优先。

### Phase 0 — 骨架与心跳（约 1-2 天）

- 仓库脚手架、pyproject、配置加载、SQLite 建表。
- 交易日历 + 作息表调度器。
- **完成标准**：进程常驻运行，在正确的 A 股时点（盘前/盘中/午休/收盘/晚间/周末）触发空的唤醒事件并落库，节假日不触发。

### Phase 1 — 模拟交易所（约 2-3 天，重点测试）

- broker + matcher + fees：T+1、涨跌停封板拒单、100 股整手、可用资金约束、交易权限检查。
- 一个 CLI：人肉扮演 Agent 手动下单，验证规则。
- **完成标准**：单元测试覆盖全部规则边界（涨停买入被拒、当日买入当日卖出被拒、资金不足、非整手、无创业板权限买创业板被拒）；CLI 能完成一买一卖全流程且账本、持仓、费用分毫不差。
- 纯逻辑无外部依赖，是全系统正确性要求最高的部分，测试重心放这里。

### Phase 2 — 信息饮食（约 2 天）

- datafeed：行情快照、日 K、个股新闻；带缓存、重试、断供降级（数据拿不到时信息流里如实说"行情加载失败"，不编造）。
- social：人气榜、千股千评、热搜。
- feed 组装器：每种作息场景一个模板（盘中场景=持仓盈亏+大盘+热榜；晚间场景=当日收盘+社媒情绪+日记回顾）。
- **完成标准**：任意时刻能生成一份人类可读的信息流文本；拔网线跑一轮不崩溃。

### Phase 3 — 首次唤醒（示踪弹，约 2-3 天）

端到端打通最小闭环：调度器唤醒 → feed 组装 → LLM 会话（工具调用循环）→ 动作执行 → 决策快照落库。

- llm.py 分层路由 + tools.py 动作空间（lookup 限次计数、order 接交易所、diary 接 memory、pass）。
- persona 加载 + leek-01 人设初稿（10 万本金工薪族，仅主板）。
- **完成标准**：一次盘中唤醒完整跑通——Agent 看到信息流、查了票、下了单（或没下）、快照里能完整回放它看到了什么和为什么。这是第一次"韭菜睁眼"。

### Phase 4 — 全作息与稳定性（约 2-3 天）

- 六种作息场景全部接通，晚间复盘场景接 diary 写入。
- 健壮性：LLM 超时重试、进程崩溃后从 SQLite 恢复状态重启、唤醒任务错过（宕机期间）的跳过策略、结构化日志。
- Docker Compose 化，Mac 上 `caffeinate` 常驻。
- 每日收盘后净值结算任务（写 nav 表）。
- **完成标准**：连续 3 个交易日无人值守运行无中断，日记连贯，成本记录在预算内。

### Phase 5 — 仪表盘（约 2-3 天）

FastAPI 只读接口 + 单页前端：

- 净值曲线（vs 沪深300 基准）、当前持仓、可用资金。
- 决策时间线：每次唤醒一个节点，点开看完整快照（它看到的信息流、思考、动作）。
- 日记流：按时间读韭菜日记。
- **完成标准**：早上打开浏览器 30 秒内能回答"韭菜昨天干了什么、为什么"。

### Phase 6 — 观察期与收尾

- 正式跑 2-4 周观察期，期间只修 bug 不动人设与信息饮食（保实验纯净）。
- 权限成长：满足条件自动解锁创业板并记为可观察事件。
- analysis/ 下第一个离线脚本：从账本统计持仓天数分布、盈利单 vs 亏损单的持有时长（处置效应的最粗信号）。
- 稳定后迁国内低配 VPS（Docker 原封搬迁）。

## 暂缓项（开跑前必须回头钉死的）

| 事项 | 最晚决定时点 |
|---|---|
| 便宜层/强层具体模型选型（换模型即换被试，开跑后不许换） | Phase 3 开始前 |
| 盘中唤醒频率具体值（成本对账） | Phase 3 开始前 |
| 社媒摘要的清洗偏差（谁做摘要、怎么控制摘要器偏见） | Phase 2 实现时 |
| 限价单跨快照存活语义 | Phase 1 实现时（一期可只做"当次快照即成交否则废单"） |
| 停牌/退市/分红送转 | 观察期遇到前（一期可先只做停牌=不可交易） |

## 主要风险

- **akshare 接口变动/被限流**：datafeed 层隔离 + 降级策略；社媒增强层挂了不影响主循环。
- **实验跑偏成"理性价投"**：这是有效结果不是 bug（ADR-0001）；应对手段只有换人设背景或调信息饮食，不许加行为剧本。
- **成本失控**：llm.py 记录每次调用 token 成本入库，仪表盘展示；超月预算报警。
